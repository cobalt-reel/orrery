# linux-dmabuf Implementation Plan

**Goal:** OpenGL and Vulkan clients render on the GPU and hand orrery their buffers (spec:
`docs/plans/2026-11-13-dmabuf-design.md`).

**Architecture:** a module `src/comp/dmabuf.rs` holding the `DmabufHandler` for `Orrery`, the advertise decision
(pure) and `Orrery::advertise_dmabuf`; the bare-metal and nested backends call it at init with their renderer's
formats, the GPU's render node and an importer over their renderer. Drawing is unchanged (Smithay's surface import
handles dmabuf buffers).

**Tech stack:** Smithay 0.7 `wayland::dmabuf` (`DmabufState`, `DmabufFeedbackBuilder`, `delegate_dmabuf!`),
`ImportDma` on `GlesRenderer`, `EGLDevice`, `DrmNode`.

**Ground rules:** as every milestone: full suite + clippy + fmt before committing, `cargo build --release`, no
references to any other project, person, machine or personal setup; the DRM backend is tested by hand only.

---

### Task 1: the module and its hooks

- `advertise(formats, render_node_known) -> Advertise { Nothing, Formats, Feedback }`, unit-tested.
- `DmabufImport` trait (`import(&Dmabuf) -> Result<(), String>`), `Orrery::advertise_dmabuf(formats, render_node,
  importer)`: builds the default feedback (falling back to a version 3 global if it cannot be built), keeps the
  global and the importer, logs what it advertised.
- `DmabufHandler::dmabuf_imported`: the importer's verdict decides `successful` or `failed`; nothing advertised
  refuses. `delegate_dmabuf!(Orrery)`.
- `Orrery` gains `dmabuf_state` and `dmabuf`; `state` gains `dmabuf: { formats, device }` (absent when none).

### Task 2: the backends

- Nested: after the first window opens, the shared renderer's formats, the render node of the host display's EGL
  device, an importer over the host's renderer.
- Bare metal: after the screens are scanned, the renderer's formats, the render node of the card node orrery opened
  (else the card node), an importer over the backend's renderer.
- Importers use `try_borrow_mut` and let a buffer through untried while borrowed (never the case today).

### Task 3: tests, docs, as built

- Headless end to end: no global, no `dmabuf` in `state`; the state view round trip carries a `dmabuf` value.
- README: a linux-dmabuf section, the `state` field, the bare-metal limits line, a checklist for the live test.
- GPU check by hand (below), the review, "As built"; then the user's live test (nested and bare metal).

## As built

All three tasks in one commit plus review fixes and docs (2026-11-13). 471 tests (3 new unit, 1 new end to end),
clippy and fmt clean.

GPU check, no monitor needed: a headless weston with its GL renderer as the host, orrery nested inside it, clients
inside orrery, on an Intel GPU (Mesa 26.2, iris and anv). Before (the previous milestone's build): `eglinfo -p
wayland` reported `llvmpipe`, `weston-simple-dmabuf-egl` failed (`No zwp_linux_dmabuf global`), `vkcube` ran by
copying through shared memory (so the README's "Vulkan clients fail to start" was wrong with current Mesa; the line
is gone with the limit). After: the log says `dmabuf: 212 format/modifier pairs, main device /dev/dri/renderD128`;
`wayland-info` shows `zwp_linux_dmabuf_v1` version 5 with that main device and tranche target; `eglinfo` reports
`Mesa Intel(R) Graphics`; `weston-simple-dmabuf-egl` and `vkcube` run, and a screenshot of the host shows the dmabuf
client's frame drawn correctly in its slot; `state` shows `dmabuf: { formats: 212, device: "/dev/dri/renderD128" }`.

Review (independent, read-only) found no bug; fixes taken: the importers purge the renderer's texture cache before
each import (buffers now enter it at creation, and it was purged only after a drawn frame, so a client recreating
buffers while nothing is drawn would have pinned dead ones); a warning when no render node is named (Mesa's GL
clients stay in software then; only Vulkan gains); `Advertise` carries the node (no `expect`); the global is
version 5 (docs said 4); `formats` counts format and modifier pairs; a client on another GPU *may* be refused;
the backends' borrow comments name the importer.

Deviations from the design: none.
